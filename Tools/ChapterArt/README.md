# Chapter personality art

The chapter **background** is the reference for this family: its landmarks, foliage,
architecture, layered silhouettes and lighting. The first brick-based tower explorations
are retired and kept only in ignored local staging. They are not shipped.

Thirty shipping sprites live in `Assets/Resources/ChapterArt`: fifteen chapter landmarks
and fifteen isolated corner decorations. The landmarks appear **only on the Chapters
journey**, as destinations on a vertical route. They do not appear as stamps on Home,
the welcome or modal headers. The route retains each chapter's completion count and
per-level medals; only unlocked destinations appear, with one unnumbered continuation
teaser. It opens near the current destination after layout settles.

The isolated ornaments frame the lower modal corners, following the active run's chapter
or the menu chapter being viewed. Blossoms, pine, vines, architectural trim, cable and
volcanic fragments follow their actual background's style and palette. They are kept
behind panel content, outside input and layout. Open layouts without a panel background
(such as the main pause view) are not decorated. Shared panel styling covers results,
pause confirmations and menu sheets; the welcome explicitly applies the Jungle trim.

The corner art is 280/250 canvas units across and overlaps the panel corner: half
the painted alpha coverage inside, half outside. `CornerLayout.json`, generated by
`process.py`, accounts for each L-shaped image’s empty space when calculating its inset. The welcome keeps its original copy, height and safe-area allowance. It retains its explicit Let's build / Skip tutorial choice.
Its HUD binding also handles a UIManager that awakens after the tutorial starts.

## Generation and extraction

- Provider: authenticated **Higgsfield CLI**, because Higgsfield MCP tools were not exposed
  in this session. Model `gpt_image_2_5`, variant `flare`, 1K, high quality, opaque green.
- `chapters.json` maps each sprite key to the actual chapter background used as reference.
- `prompts.json` contains the exact final prompts. `manifest.json` records shipping asset
  paths, generation job IDs, settings, prompts and PNG byte sizes.
- `generate.py submit Jungle Japan` explicitly creates missing jobs only. Submit at most
  eight pending jobs at once; every new job consumes credits. Existing IDs are reused.
- `generate.py fetch` retrieves existing jobs. No automatic paid retries.
- `process.py` checks the green background, extracts alpha, suppresses edge spill, crops,
  downsamples with alpha-aware filtering and writes optimized lossless 512px RGBA PNGs.
  Empty source folders fail without changing outputs. Partial batches merge into the
  existing manifest and corner layout; all images, metadata and the contact sheet are
  prepared before publishing. Individual files are replaced atomically.
  Run `python3 Tools/ChapterArt/test_process.py` for offline regression checks.
- Local masters/jobs are under ignored `raw/background-led`; visual captures under ignored
  `review`. Rejected outputs are retained locally, including one painted checkerboard and
  one Giza render with an unsuitable haze edge. Neither is installed.
- Python tools use Pillow and NumPy plus the authenticated `higgsfield` executable.

## Unity import and memory

`ChapterArtImporter` applies sprite import, full-rect geometry, alpha transparency,
bilinear filtering, clamp wrapping, no mipmaps and no CPU-readable texture copy. Android
and iOS use ASTC 6×6 at a maximum of 512px. A square sprite's compressed texture payload
is about 116 KiB (excluding Unity object overhead); thirty total about 3.39 MiB if all
are resident. PNG source size is about 5.29 MiB; final build size is platform-dependent.
`ChapterArtwork` adds no permanent texture cache; Unity can reclaim unused art when it
unloads unused assets. Every decorative Image has raycasts disabled and ignores layout.
Unknown/custom chapter keys simply omit the decoration.

## Verification

Copy `ChapterArtChecks.cs.txt` into `Assets/SourceFiles/Scripts/Editor/ChapterArtChecks.cs`,
refresh Unity, and invoke `ChapterArtChecks.Run()` in Edit Mode. It validates all thirty
sprites and mobile import settings, nonblocking decoration, chapter restyling and fallback.
`ChapterArtChecks.Render()` checks and captures the journey with two cleared chapters and
one current chapter, five decorated level sheets and the tutorial result. It uses temporary
in-memory progress, with no user save or progression writes. Captures isolate page content;
global account chrome and bottom navigation are omitted. Remove temporary fixtures and
`.meta` files after checking.

Also run `Tools/TutorialChecks` and `Tools/ProgressionChecks/HudObjectiveChecks.cs.txt`.
The tutorial fixture checks the decorated welcome across six aspect ratios, the late HUD,
explicit choice, gentle descent/hover and the 25-standing-block goal.

Validated in Unity on 2026-09-10: 184 art/import/input checks, 207 tutorial checks
and 69 HUD objective checks passed. The journey and five modal captures also passed
eight content assertions; welcome and results captures were inspected. Temporary Editor
fixtures were removed. Physical-device visual testing remains a manual follow-up.
